## 1 项目目标与交付范围

第三组建设一个通用词对衔接模块：输入两个已收录词的机器人动作及其允许的进入、离开条件，自动生成连接轨迹，并提供独立验证结果。最终要回答三个问题：是否找到了合格衔接、为什么合格或失败、如何在另一环境复核。

本期以第二组医院词库的 35 个词为固定范围。默认同时检查不同词和同词重复，共 **35 × 35 = 1,225 个有向词对**，其中不同词 1,190 对、同词 35 对。报告始终分列两部分；如果团队正式将同词重复排除，应发布范围变更记录，不能在计算通过率时临时删除。

`A → B` 与 `B → A` 是不同任务。`A → A` 的测试要保留两次词动作及必要边界，不能通过删除一次动作或只检验零长度连接获得通过。

“任意两个词”指冻结词库中的任意有序组合。未知词必须明确返回不支持；新增词进入词库后须增量验证。词对在运动学上可连接，也不表示它们构成正确的手语句子。

### 1.1 成功层级

| 层级 | 完成内容 | 可以声明的能力 |
|---|---|---|
| L1 覆盖与诊断 | 1,225 对全部完成运行或明确记录阻塞、超时与错误 | 全词对已扫描，具备完整问题清单 |
| L2 仿真衔接 | 1,225 对全部满足冻结的几何、限位、耦合、边界和平滑规则 | 当前词库与模型下，全词对通过规定的仿真检查 |
| L3 组合与可理解性 | 多词组合通过，规定的人工评审完成 | 在已评审范围内支持组合展示与可理解性结论 |
| L4 实机执行 | 真实硬件约束、控制、动力学与受控实验通过 | 仅在已验证的设备和条件下支持执行 |

第三组核心工程目标是 L2，并完成多词组合的工程验收。语言评审需要相应评审人员参与，实机执行单独立项。不能把 L1 的“全部跑过”或 L2 的采样几何结果写成 L3、L4 已完成。

## 3 三组职责与接口

### 3.1 责任边界

| 团队或角色 | 负责内容 | 必须交给下一方的证据 |
|---|---|---|
| 第一组 | 文本到合法 gloss 序列，拒绝与澄清行为，句子层语言规则 | 词表版本、序列、错误状态、代表输入 |
| 第二组 | 每个词的示范来源、机器人动作、语义核心、允许进入离开窗口、动作质量 | 轨迹与元数据哈希、窗口说明、缺陷与可修改范围 |
| 第三组成员甲 | 端点策略、候选路径、手指策略、搜索与时间参数化 | 算法实现、配置、单元测试、失败解释 |
| 第三组成员乙 | 全词对运行器、独立验证器、矩阵、续跑、回放与集成 | 验证报告、回归、数据清单与演示 |
| 两名成员共同 | 困难词对诊断、互审、实验对照、最终报告 | 可复现交付与签核记录 |
| 指定交叉评审者 | 在冻结版本上执行复核与人工检查 | 不参与本轮调参的复核记录 |

责任是建议分工，不代表已经指定具体同学或获得第三方承诺。涉及公共词表、关节合同与动作核心的变更，由当轮协调人组织三组确认。

### 3.2 拟定输入与输出

规划接口拟为：

```python
plan_pair(source_gloss, target_gloss, *, library_version, policy, seed)
```

输入还需绑定机器人模型、关节顺序、词动作哈希、端点窗口、边界位置与导数、约束、候选和搜索预算。核心规划器只依赖动作合同；文本识别和语义模型恢复不应阻塞词对离线扫描。

输出包括过渡轨迹、实际进入离开帧、采用方法、状态、约束指标、验证范围、资源版本与复现信息。输出必须能直接供整句组装器读取。失败时可以保存诊断轨迹，但不能自动交给普通播放或执行入口。

## 4 冻结词库与逐词审计

先形成 `library_manifest.json` 和 `word_audit.json`，再进行全词对比较。冻结内容包括 35 个 gloss、轨迹文件、SHA-256、采样时刻、53 个具名关节、独立坐标与耦合关系、机器人几何、依赖版本和检查策略。

每个词至少审计以下内容：

1. 数组维度、有限数值、时间戳严格递增、采样率与关节顺序。
2. 关节限位、耦合误差、速度异常和缺帧。
3. 候选进入帧、离开帧的几何间隙与边界导数。
4. 词内动作的碰撞、关键手形、掌向、双手相对位置和既有缺陷。
5. 第二组提供的语义核心与允许调整窗口。
6. 来源许可记录与文件可获得性，防止复现依赖未交付的输入。

端点窗口不能仅按“允许裁去 10%”自动生成。现有 `sign_frames` 来源于运动几何，不等于经过语言评审的语义核心。窗口需标明工程审核和语言审核的各自状态。未确认可调整窗口时，默认保留原端点；不合格端点记录为阻塞项。

### 4.1 NURSE 个案处理

保留 f80 和严格上限 f81 的报告与对比。f80 为约 10.13% 例外；交接记录中 f81 存在约 28.43 mm 的端点穿透，不能把改回 f81 当成已解决问题。

待决事项是是否保留这个特定动作版本、特定离开帧的裁剪。确认记录必须绑定动作哈希、帧号、比例、理由、确认人和日期。新动作版本不能继承旧帧号的例外。未确认前可以进行明确标识的研究对照，最终正式通过集不能默认为已批准。

### 4.2 词性与运动特征

可沿用已有的 part_of_speech 与 sentence_role 作为统计和展示字段，再逐步补齐医院词表。缺少词性不应阻塞几何扫描，词性也不能决定某个词对能否衔接。

候选生成更直接使用双手参与情况、手腕位置与掌向、手形、双手交叉状态、关节余量和边界运动方向。上述运动特征应由冻结轨迹或模型计算，并保留计算版本；人工添加的语义标签独立注明来源和审核状态。

## 5 合适衔接的工程定义

### 5.1 硬约束与软目标

先检查硬约束，再比较质量。碰撞、限位、耦合、核心保留或边界连续性失败，不能用更短时长或更好平均分抵消。

| 项目 | 拟采用口径 | 冻结方式 |
|---|---|---|
| 轨迹有效性 | 有限数组、严格递增时间戳、统一关节合同 | T00 固定 |
| 端点位置 | 连接实际选定帧；建议数值误差不大于 1e-6 rad | T00 确认精度，保留原样本 |
| 关节限位与耦合 | 按模型和当前合同检查全部输出坐标 | T00 固定逐关节容差 |
| 采样间隙 | 沿用当前移动碰撞对至少 +2 mm 的研究门槛 | 明确模型、过滤规则与采样分辨率 |
| 速度 | 当前手臂 15 rad/s、手指 10 rad/s 仅作仿真基线 | 硬件规格到位后另设执行限制 |
| 速度与加速度衔接 | 测量两侧不连续量，冻结每类关节容差 | T03 在开发集与数据质量评估后固定 |
| 加速度与 jerk | 报峰值、分位数与 jerk 平方积分，设置数值质量门槛 | T03 冻结，不能事后按最终测试调阈值 |
| 过渡时长与停顿 | 沿用 0.3 s 逐腿下限作基线；另设最大时长与停顿规则 | T03 根据开发样本和演示要求固定 |
| 动作核心保留 | 对冻结核心区逐样本核对；裁剪、重定时另行记录 | 第二组三组共同确认 |
| 同词重复 | 保留两次动作及可辨识边界 | 单独检查 35 对 |

上表中的待定参数不是默认通过。参数未冻结时，运行可输出开发指标，但不能获得最终验收签核。2 mm 和当前速度值也不是实机安全认证。

软目标包括较短的合理时长、较小的绕行、较低的 jerk、少量非必要停顿和稳定的手形变化。首先采用可解释的排序规则；若改用加权分数，应记录量纲归一化、权重与开发依据，并报告各分项，避免单一总分掩盖问题。

### 5.2 碰撞与连续性范围

播放仍可采用 30 fps，但验证必须沿实际插值曲线独立采样，而不是只重复检查播放帧。RRT 路径、平滑后的路径和重新计时后的最终轨迹都要复查。

首轮记录当前分辨率，随后在开发与验收中进行 2 倍、4 倍加密敏感性检查，并对小间隙、高曲率、高速度区间使用自适应细分。加密通过仍只支持规定采样下的结论；需要连续无碰撞声明时须增加连续检测或保守界证明。

检查器必须列出当前同手排除、静态对分类和上游碰撞几何范围。先审查这些过滤条件的依据，再决定最终检查范围，不得通过删除困难碰撞对提高通过率。任何未建模接触都要反映在验证范围字段中。

## 6 通用规划器改造

### 6.1 分层候选流程

1. **输入与端点检查**：拒绝未知词、损坏动作、无效窗口和不满足约束的端点。
2. **直接连接**：使用能表达边界条件的多项式或样条，先验证最短的简单候选。
3. **通用 IK 绕行**：依据机器人坐标、手腕位置和空间余量生成外侧、上方、前方等候选。
4. **双臂协调与回撤接近**：评估同步或错峰策略及已验证的公共中间姿态；中立姿态本身和两条连接边均须检查。
5. **通用有界搜索**：对仍失败且端点有效的词对开放 RRT，取代两对词白名单。
6. **路径简化与时间参数化**：限制加速度、jerk、停顿和速率，然后重新验证。
7. **质量选择**：在全部硬约束通过的候选中按冻结规则选取最优候选；输出候选摘要和理由。

保留当前 R13c 为可回归的基线。既有特例先迁入带版本和理由的配置，再用通用策略替代；不能一次删除后失去原来通过的词对，也不能继续无记录地增加词对专属分支。

### 6.2 位置速度与加速度边界

过渡段自身的零速度、零加速度端点不一定匹配词动作的边界。规划器应使用源词尾部和目标词头部的固定短窗口估计导数，并记录估计窗口、滤波和单位。

优先在允许窗口中寻找既保留词核心又具有适合边界条件的帧；也可在允许的非核心区缓入缓出。若使用边界条件多项式，必须检查可能产生的中间越界。不能通过改动受保护词核心获得数值平滑。

中间 RRT 节点不应因为逐边停下而形成大量可见顿挫。比较保节点的时间参数化与经过验证的平滑方案；路径变化后重新检查碰撞。速度、加速度连续性以最终完整拼接轨迹为准。

### 6.3 手臂与手指

当前 RRT 搜索 14 个手臂关节。扩展后仍可先保留这一低维搜索，但手指、耦合关节及其他输出坐标必须随完整候选一起检查。

为手指提供明确策略，例如保持源端手形后渐变、按路径进度渐变或先形成目标手形；策略切换必须在允许窗口内，并记录是否产生碰撞、耦合偏差或明显多余手势。手指策略失败应有独立原因码，不能统称“手臂路径不存在”。

### 6.4 搜索预算与复现

验收模式使用固定种子、固定节点或碰撞查询数量、固定候选顺序和线程配置。墙钟时间作为外层资源保护；触发后标记 TIMEOUT，不当作数学不可行。

开发模式可设置较小预算，困难对再运行扩展预算。每次重试保留 attempt_id，矩阵同时报告首次成功率、重试后成功率和预算，避免只呈现最佳一次结果。耗时日志与轨迹内容哈希分开。

## 7 数据结构与结果状态

拟增加以下文件。名称可以在实现前调整一次，但输出合同须先冻结。

| 文件 | 用途 |
|---|---|
| `config/transition_policy.json` | 所有阈值、预算、采样策略、手指策略和例外 |
| `library_manifest.json` | 词库、动作、机器人及依赖的版本和哈希 |
| `word_audit.json` | 逐词端点、核心、窗口和缺陷 |
| `pairs.jsonl` | 每次词对运行的结构化记录 |
| `matrix.csv` | 每个词对一个最终状态的可读矩阵 |
| `manifest.json` | 本次运行状态、配置、文件列表和校验值 |
| `trajectories/` | 待验收候选和失败诊断轨迹 |
| `verification/` | 独立读取轨迹后的检查结果 |
| `review/` | 代表视频、人工检查表和决定记录 |

### 7.1 状态合同

每对词有一个互斥主状态，并另附多个原因码。

| 状态 | 定义 |
|---|---|
| `NOT_RUN` | 尚未执行 |
| `PASS_SIM` | 最终保存轨迹通过本版全部仿真硬约束与独立复查 |
| `SOURCE_NEAR` | 仅通过端点相对门槛，未通过绝对间隙要求 |
| `BLOCKED_ENDPOINT` | 端点或允许窗口不合格；原因中标明 source、target 或两者 |
| `BLOCKED_INPUT` | 词库、文件、关节合同或冻结元数据不满足要求 |
| `FAILED_SEARCH` | 给定预算内未找到路径，不等于已证明不存在路径 |
| `FAILED_QUALITY` | 存在路径，但边界、手指、平滑或时长规则未通过 |
| `TIMEOUT` | 资源保护触发，结果未完成 |
| `ERROR` | 程序或环境异常 |

保留对旧 `PASS`、`FAILED`、`needs_group2_fix` 的导入映射，但不能只凭历史状态直接生成 `PASS_SIM`。待确认例外、未冻结阈值和未完成复查的候选均不得进入最终通过集。

运行器逐对计算、逐对落盘，采用临时文件加原子替换；中断后能从已验证检查点继续。续跑前校验代码、策略、模型和输入哈希。任何影响结果的版本变化都进入新 run_id，避免把新旧结果混为一轮实验。

粗扫可以只保存摘要以定位成本，但粗扫不用于最终验收。所有拟计入 `PASS_SIM` 的词对必须保存完整轨迹并由独立验证器重新读取。NPZ 可放在外部或忽略的结果目录，无须加入 Git；最终包必须包含可获取的轨迹、清单和哈希。

视频仅为全部失败类型、边界案例、各动作姿态代表和最终演示生成。失败轨迹也应限量保留足够诊断信息，避免大量相同错误占满磁盘。

### 8.1 资源预算

先跑覆盖简单、绕行、双手交叉、端点异常和 RRT 的 30 至 50 个词对，测得阶段耗时、内存、轨迹大小与失败率，再估计总成本。该小集属于开发与性能校准集。

若 1,225 对都耗尽现有 120 秒搜索预算，单进程仅搜索就约需 **40.8 小时**，还未计前序候选和验证。因此采用“先端点筛查和便宜候选、再集中搜索残余困难对”的分轮方式。并行数依据内存与 MuJoCo 模型隔离测量后固定，不能将无限重试作为完成策略。

新增第 36 个词时，需要增加 71 个有向词对，包含新词自对。单个词轨迹更新时，至少使涉及该词的 69 对失效；若共享模型、全局碰撞分类或策略同时变化，则可能需要全量重新验证。

## 10 失败归因与修复闭环

按缺陷根因建单，而不是按每个失败词对重复开单。一个不合格端点可能影响大量入边或出边；优先修复影响面最大的词。

- **输入或端点缺陷**：第二组主责修订动作、核心或窗口，第三组提供帧号、最差碰撞对、曲线和复现命令。
- **搜索不足**：第三组检查候选覆盖、预算、搜索空间与路径质量；预算内失败只能说明当前方法未找到解。
- **手指或耦合缺陷**：定位手形时序、非手臂自由度处理和耦合恢复，独立报告。
- **边界或时长缺陷**：调整允许窗口、边界条件与时参化；不能只把播放整体放慢后忽略语义节奏。
- **模型或碰撞规则缺陷**：核实上游几何与过滤假设，任何修改单独版本化并重跑受影响范围。
- **环境错误**：归入 ERROR，修环境后重新运行；不能计为算法失败或成功。

每项修复包含最小复现、修改内容、预期影响范围、回归结果和剩余限制。原始证据保留，新候选写新目录。

## 11 多词序列与组合验证

词对测试应直接使用“词 A 允许离开的边界 → 词 B 允许进入的边界”。句首从中立姿态起势、句尾返回中立姿态另外验证，避免将两词演示的首尾特殊处理混入词对定义。

对 `A → B → C`，同时确定 B 的进入和离开条件，检查进入帧不晚于离开帧，且受保护核心完整保留。如果端点选择依赖上下文，组装器需联合选择兼容的入口、出口方案；不能机械拼接两个各自通过但互相冲突的词对结果。

验证范围至少包括：

1. 当前固定 10 句的回归。
2. 全部中间词的窗口兼容性枚举；固定词级窗口时每词一次，若采用词对相关窗口则枚举三词元数据组合。35³ 为 42,875 个组合，先做便宜的窗口和核心一致性检查。
3. 冻结不少于 100 条三词序列，覆盖每个词作为中间词、危险端点与双手交叉；这是工程目标，实际数量在 T03 固定。
4. 不少于 20 条五词序列以及重复词序列，覆盖不同节奏与手形切换。
5. 对最终展示的每条完整序列逐帧及加密检查，覆盖原词片段、过渡和两侧边界。

抽样多词序列通过只能支持已测组合范围，不能证明任意长度序列均可用。词内原有缺陷必须单列；它们不应被“过渡通过”掩盖。

## 12 对照实验与人工评价

采用相同词库、端点政策、模型、时间和碰撞规则比较：

- B0：固定时长的直接插值基线；
- B1：现有 R13c 分层规划器；
- B2：本计划通用规划器；
- 可选消融：关闭 RRT、关闭导数匹配、关闭手指策略，定位收益来源。

主实验固定相同端点，防止把裁剪收益误算为规划算法收益。允许不同窗口政策时，另做端点策略实验并报告裁剪量。B0 本身若不满足约束，正常记录失败，不放宽规则。

核心指标包括：扫描覆盖率、绝对仿真通过率、首次与重试成功率、各失败原因、时长与运行成本、间隙、速度、边界导数跳变、jerk、绕行长度和核心保留情况。使用全 1,225 对作分母，并分列 1,190 非重复和 35 自对；另列有效端点子集成绩时同时给出数量，不能替代全范围结果。

开发时可扫描全矩阵用于工程修复，但这时矩阵成绩属于开发验收。若需要宣称对未见词对的泛化，应预先冻结独立词对集，调参不可查看其结果；同一词对的重采样、时长变化和重复种子不能分散到训练与独立测试两侧。

人工检查先看全部失败类型和边界词对，再抽取分层随机通过样本。至少两名工程检查者独立记录顿挫、多余绕行、手形不连贯和词动作可辨识问题。需要语言结论时，请具备相应能力的评审者进行词识别与连贯性评价，先固定题目、评分表和展示顺序，再记录实际参与人数。无合格语言评审时，该项保持未验证。

## 13 训练模型的可选研究路线

实现当前 35 词的全词对覆盖，可以先采用几何规划和搜索。深度学习不作为扫描与验收的前置依赖。

若课程要求第三组必须包含学习算法，需单独冻结研究问题，例如“预测合适的时长和中间姿态，以减少搜索成本”。训练目标可以来自已经验证的规划轨迹，但必须记录来源与验证版本，不能把规划器自生成轨迹称为真实人类衔接示范。

建议先学习候选排序或初值，输出仍经过相同验证器；模型失败时允许回退到通用规划器。只有同预算对照显示成功率、质量或速度收益，才将学习模块纳入主线。训练、开发、独立测试划分按词对或来源整体隔离；如主张对新词泛化，还需独立留出词及其全部相关词对。

若课程仍要求“十类 ID 条件动作生成”，应将其作为额外交付需求登记。完成本规划书的衔接模块并不自动满足该学习模型要求。

## 14 风险与处理

| 风险 | 触发信号 | 处理与责任 |
|---|---|---|
| 原词端点缺陷影响多对 | 同一词入边或出边集中失败 | 甲整理根因，第二组返修，乙重算受影响范围 |
| 裁剪改变动作含义 | 核心被删、窗口未确认 | 暂停该候选正式验收，保留研究对照与待决记录 |
| 碰撞漏检 | 加密后状态变化 | 提高或自适应采样，修复后复查受影响矩阵 |
| RRT 成本过高 | 大量对耗尽预算 | 分轮搜索、缓存、固定预算和明确 TIMEOUT |
| 手指造成新碰撞 | 手臂通过而整轨迹失败 | 调整手指时序或搜索范围，独立归因 |
| 通过率提高但动作不自然 | 顿挫、长停顿、绕行过大 | 使用导数与时长门槛，加入人工对照 |
| 两两通过但整句失败 | B 的入口出口冲突 | 联合窗口选择、三词兼容检查及整句验证 |
| 版本混用 | 同词名称对应不同哈希 | 缓存失效，禁止旧报告直接复用 |
| 外部评审或动作返修延误 | 对方未交付所需证据 | 交付实际达成层级，列明后续责任与日期 |
