## 先建立项目地图

输入的英文整句 → 三条候选含义目录 → 公共 guard 与选择器 → 合法动作 ID 或不执行 → 动作审查状态与轨迹约束 → MuJoCo 候选预览 → 未来的真人理解评估。

| 层 | 输入与输出 | 当前证据 | 不能越过的结论边界 |
|---|---|---|---|
| 表达范围 | 英文整句 → HELLO / THANK_YOU / PLEASE_WAIT 或拒绝 | `data/catalog.json`、完整句含义限制 | 三个 ID 不是任意文本翻译器；附带意图不能只执行其中一段 |
| 文本选择 | 原句与目录 → Selection | exact、真实 MiniLM、显式启用的本地 LLM 研究后端 | 返回合法 ID 不等于含义选择正确 |
| 动作生成 | 人工手腕目标与耦合手型 → `[T,J]` 关节轨迹 | 人工关键帧、有界数值 IK、smoothstep 插值与运动学播放 | 未提取真人三维动作，也没有训练手语动作模型 |
| 机器人验收 | 轨迹和模型 → 限位、耦合及几何报告 | 固定底座 G1 + Inspire DFQ 候选；保存了失败迭代 | 简化碰撞几何检查不等于真实机器人碰撞安全或动力学跟踪 |
| 语言与使用者 | 机器人表达 → 含义复述及偏差 | THANK YOU、WAIT 官方视频已实际播放并观察 | WAIT 词例不是完整礼貌请求；尚无 ASL 使用者评审或医疗验证 |

必须先掌握目录含义、输入输出契约、基础 FK/IK、误差分母与冻结实验；然后才能解释模型输出和轨迹。进阶工作是新标签协议、非手部信息、真人理解实验及真实跟踪。现阶段可以暂缓大规模训练、端到端生成和多语言临床部署，避免以复杂模型掩盖表达本身尚未确认的问题。

## 读懂三张图

图表为英文标签，便于放入英文 slides。可直接使用 PNG/SVG；需要可编辑原生图表时，从 `analysis.json` 的 `chart_data` 取系列和计数，不从图片估数。

| 图表文件 | 回答的问题 |
|---|---|
| `supported_outcomes.png` / `.svg` | 对 30 条范围内输入，选对、误拒、选错 ID 和 error 各有多少？ |
| `out_of_scope_outcomes.png` / `.svg` | 对 30 条范围外输入，有没有错误执行？ |
| `llm_execution_paths.png` / `.svg` | 60 条决策中，哪些由 guard 完成，哪些真的请求了模型？ |

把支持输入数记为 `S`，它由四种互斥结果组成：`S = C + R + W + E_s`。`C` 是正确 ID，`R` 是误拒，`W` 是执行错误 ID，`E_s` 是 error。库外输入数 `U = J + F + E_u`，`J` 为正确拒绝，`F` 为错误执行，`E_u` 为 error。当前协议将库外的 clarify 与 unsupported 都算正确不执行，而 error 不算成功拒绝。

整体行为准确率为 `(C + J) / (S + U)`；支持输入选对率为 `C/S`；库外错误执行率为 `F/U`；执行覆盖率为 `(C+W+F)/(S+U)`；执行正确率为 `C/(C+W+F)`，若没有执行则为 null。不同分母回答不同问题，不能只选最好看的一个。

| 从原始记录重算 | exact + guard | MiniLM + guard | 本地 LLM + guard |
|---|---:|---:|---:|
| 整体行为正确 | 38/60 | 47/60 | 48/60 |
| 支持输入正确 ID | 8/30 | 17/30 | 20/30 |
| 支持输入误拒 | 22/30 | 13/30 | 7/30 |
| 支持输入错误 ID | 0/30 | 0/30 | 1/30 |
| 支持输入 error | 0/30 | 0/30 | 2/30 |
| 库外正确拒绝 | 30/30 | 30/30 | 28/30 |
| 库外错误执行 | 0/30 | 0/30 | 2/30 |
| 执行正确率 | 8/8 | 17/17 | 20/23 |

全部 60 条题目由 agent 拟写并初标，尚未人审；不能声称这是总体准确率，更没有统计显著性结论。LLM 相对 MiniLM 只多一个整体正确案例，却引入了库外错误执行。因此“80% 高于 78.3%”不足以宣布 LLM 更适合默认使用。exact 和 MiniLM 的本次 0/30 错误执行也不是总体零风险。

LLM 的 25 条 guard 决策中，23 条库外被正确拒绝、2 条支持输入被误拒。实际收到 HTTP 回答的 35 条中，20 条支持输入选对、5 条库外正确拒绝、5 条支持输入误拒、1 条错误 ID、2 条错误执行、2 条非法输出。该子集包含 28 条支持和 7 条库外，与 guard 子集的构成明显不同。不能用 `23/25` 与 `25/35` 宣称规则比模型强，也不能把全部 48 个正确结果归功于模型。

计时也有同样的边界：整体 LLM selector 的中位数为约 18.77 ms，实际 HTTP 子集约 20.06 ms；两者均含程序调用开销。服务已提前启动，一个额外 readiness 请求未计入 60 题，这不是从零启动时间，也不是机器人首次可见动作的端到端延迟。

## 用失败解释机制

下列预期标签均指当前冻结草稿协议，不意味着经过 ASL 或语言学人审。`analysis.json` 保存了原始行及确定性的选择规则：在指定方法/失败类别/执行路径内取最小 case ID，同时列出全部两条 LLM 库外错误执行。它们是诊断例子，不是抽样总体。

| Case ID | 输入或现象 | 观察到的失败 | 可以提出的诊断；不能直接当事实的推断 |
|---|---|---|---|
| `test-003` | `Hello to you!` | exact 误拒 | 固定别名覆盖有限；不说明机器人不会做 HELLO |
| `test-006` | `Good to see you!` | MiniLM 误拒 | 当前相似度/目录范围没有接受；人审仍需检查它是否与 HELLO 完全等义 |
| `test-016` | `Much appreciated!` | LLM 选择 HELLO | 白名单限制住了输出空间，但不能保证语义正确 |
| `test-017` | `I really appreciate what you did.` | guard 误拒，无模型请求 | 规则因 `what` 触发元语言判断；不能把这次失败归给 LLM 推理 |
| `test-021` | `Wait a moment.` | LLM 输出包含 `THERE_ARE_NO_SUCH_INFORMATION, PLEASE_WAIT`，严格解析为 error | 客户端没有从杂乱文本里截出看起来正确的 ID；这种拒绝保留了格式失败证据 |
| `test-025` | `Give me a moment, please.` | 模型返回 CLARIFY | 有真实模型请求；需与 guard 误拒分开分析 |
| `test-038` | `She wants to thank you.` | 错误执行 THANK_YOU | 当前协议要求说话者直接感谢听者；第三方角色信息没有得到正确保留 |
| `test-040` | `They thanked me yesterday.` | 错误执行 THANK_YOU | 描述过去事件被当作当前表达；仅抓关键词不能满足整句等义 |

下一版先由 C1 组织人工复核标签与语用边界，保留分歧并另存版本；B1/B2 只使用新的开发资料制定修改协议，随后交新的测试集验证。不能把这八个例子补进旧提示词，再在同一冻结集上宣布新的独立改进。

## 五个核心思维模型

| 思维模型 | 是什么、为什么成立 | 何时使用与何时失效 | 面试/工程用法 |
|---|---|---|---|
| 有类型的编译流水线 | 文本经含义选择变成受限 ID，再由已知轨迹执行；每层显式契约减少接口歧义 | 适合小目录与可审查动作；合法 ID 仍可能语义错误，目录不全时不能硬匹配 | 先画各层输入输出，再说哪些错误在该层可检测 |
| 分层验收 | 格式、文本语义、关节几何、动力学和真人理解是不同目标 | 适合多模块机器人系统；只用单层指标代表整体时失效 | 将“测试通过”后面补上具体测试对象和未测对象 |
| 拒绝是一种有代价的决策 | 多执行与少误执行之间有取舍；全部拒绝也可能得到不低的总分 | 用于白名单检索、阈值选择和模型比较；错误代价未定义时不能选出普适最优方案 | 同时报告错误执行、误拒与覆盖率，不只报 accuracy |
| 按实际执行路径归因 | 同一按钮可能经过规则、模型或错误分支；质量与延迟必须归到实际运行的部分 | 用于混合系统和性能测试；把 guard 子集当随机模型样本时失效 | 保留 request/response 证据，区分模型问题、规则问题与权限问题 |
| 约束下的动作映射 | 人体目标经机器人结构、限位、耦合与时序约束映射为关节轨迹 | 适合机器人与人形差异较大的动作复现；低 IK 残差只证明拟合人工目标，不证明语言等价 | 先问目标来自哪里、可观测什么，再选关键帧或 retargeting |

这五个模型连接起来的主线是：先确定完整含义，再约束表示，逐层验证，最后按实际执行路径解释失败。

## 三个需要有条件作答的争议

### 1. LLM 总分更高，是否应替换语义匹配？

支持替换的观点看重更多改写被接受：本次 LLM 支持选对 20/30，MiniLM 17/30。反对直接替换的观点看重错误执行：LLM 库外误执行 2/30，而 MiniLM 此次为 0/30；LLM 还发生错误 ID 和非法输出。

两种观点隐含了不同错误代价。若漏掉表达的代价很高且允许人工确认，较高覆盖可能有价值；若错误表达代价很高，应先约束错误执行并考虑澄清。当前没有定义或验证真实使用场景的代价，也没有人审数据，不能宣称哪种方法普遍最优。实践中保留 LLM 的 `not_accepted_for_default` 状态，以新开发协议验证，而非以一分差距推翻启用门槛失败。

### 2. 有 WAIT 和 PLEASE 词例，是否足以称完整“请稍等”？

词例路线可以快速建立有限动作目录，便于拆分手型、掌向、位置和运动方向；完整表达路线要求语境、顺序、停顿、面部和其他非手部信息。现有证据实际支持 WAIT 词例观察，没有完整 PLEASE_WAIT 请求的真人示范或机器人理解评审。

把两个英文词一一拼接隐含了“词序和礼貌表达跨语言保持不变”的假设，当前未验证。课程几何演示可保留软件 ID，但必须显示 WAIT 候选和完整表达未核验。面向新加坡使用者还需独立选择和验证语言，当前 ASL 不能直接代表 SgSL。实践中的下一步是完整请求参考和不带字幕的真人含义复述，而不是先增加更多未核验词条。

### 3. 人工关键帧是否不如从视频重定向？

人工关键帧便于明确约束、定位关节问题并在短期内得到可解释原型；视频重定向可能保留更多细节和自然时序，但依赖手部可见性、姿态估计、尺度与坐标约定以及人体到机器人的结构映射。单目视频中的遮挡、深度和接触状态不能凭观看精确恢复。

当前实际路线是观看示范后制作人工目标，使用有界数值 IK 和插值，没有执行三维人体重建、Mink/dex-retargeting 对照或动作学习。THANK YOU 的近唇位置、掌向和向前略下的路径已用于校准，但机器人仍有脸部间隙、并指能力与表情缺口。实践中先用关键帧建立验收基线；若取得合法且适用的三维数据，再固定相同任务、机器人和评价协议比较重定向。不能预先声称一种路线更准确。

## 复现这次只读分析

脚本 `scripts/analyze_evaluation.py` 只使用 JSON 中的原句、预期 ID、status/action_id 和 HTTP 元数据，不导入语言选择器。输入形状是三方法各 60 行，输出是离散计数与三组图；所有已有结果目录拒绝覆盖。
